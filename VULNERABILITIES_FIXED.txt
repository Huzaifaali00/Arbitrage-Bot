[1] REENTRANCY GUARD FAILURE
    BEFORE: ❌ Custom implementation locks permanently on revert
    AFTER:  ✅ OpenZeppelin ReentrancyGuard with proper handling
    IMPACT: Contract was permanently locked after any failed trade

[2] FLASH LOAN CALLBACK EXPLOITATION
    BEFORE: ❌ Only checks msg.sender == pool, no approved pool validation
    AFTER:  ✅ Multi-layer validation: pool approved + deadline + token approved
    IMPACT: Unauthorized token transfers possible
    FIX:    Added approvedPools mapping and callback validation

┌─ HIGH SEVERITY ─────────────────────────────────────────────────────────────────┐

[3] NO POOL WHITELIST
    BEFORE: ❌ Any address accepted as pool parameter
    AFTER:  ✅ Must call approvePool() first with validation
    IMPACT: Malicious pool could execute arbitrary code
    FIX:    mapping(address => bool) public approvedPools
            modifier onlyApprovedPool(address pool)

[4] UNBOUNDED HOPS ARRAY
    BEFORE: ❌ No limit on hops.length, causes gas exhaustion
    AFTER:  ✅ Limited to 10 hops maximum
    IMPACT: DoS attack by passing 1000+ hops
    FIX:    uint256 private constant MAX_HOPS = 10

[5] NO TOKEN VALIDATION
    BEFORE: ❌ Any token accepted, breaks with fee-on-transfer tokens
    AFTER:  ✅ Must call approveToken() with ERC20 validation
    IMPACT: Profit calculation fails with non-standard tokens
    FIX:    mapping(address => bool) public approvedTokens

└─────────────────────────────────────────────────────────────────────────────────┘

┌─ MEDIUM SEVERITY ──────────────────────────────────────────────────────────────┐

[6] UNSAFE ETH TRANSFER
    BEFORE: ❌ Uses .transfer() with 2300 gas limit
    AFTER:  ✅ Uses .call() pattern with dynamic gas
    IMPACT: Fails with smart wallets and multisigs
    FIX:    (bool success, ) = payable(recipient).call{value: amount}("")

[7] NO SWAP DEADLINE
    BEFORE: ❌ No deadline, pending tx executes hours/days later
    AFTER:  ✅ Per-transaction deadline validation
    IMPACT: Stale transactions confirmed at wrong prices
    FIX:    struct includes deadline field, callback validates

[8] WEAK CALLBACK VALIDATION
    BEFORE: ⚠️  Only checks msg.sender == pool
    AFTER:  ✅ Validates pool approved, deadline, token approved, amounts
    IMPACT: Pool spoofing possible
    FIX:    require(approvedPools[pool], "unapproved pool")
            require(deadline >= block.timestamp, "expired")
            require(approvedTokens[token], "unapproved token")

[9] SINGLE OWNER CONTROL
    BEFORE: ❌ No multi-sig, typo in owner transfer = permanent loss
    AFTER:  ✅ Two-step ownership transfer with acceptance
    IMPACT: Accidental loss of control
    FIX:    _transferOwnership() needs _acceptOwnership() confirmation

[10] BUILDER TIP LOGIC FLAWED
     BEFORE: ❌ Deducted after profit validation, confusing accounting
     AFTER:  ✅ Deducted properly before validation or clearly documented
     IMPACT: User thinks they got X profit but actually got X - tip
     FIX:    Clearer separation of concerns

     BEFORE: ❌ No events emitted for any operations

[12] NO EMERGENCY PAUSE
     BEFORE: ❌ Cannot stop trading if vulnerability discovered
